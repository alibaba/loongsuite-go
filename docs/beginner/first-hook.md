# 7. Hands-on: Your First Custom Hook

**Question:** How can you see for yourself that a hook runs before and after the target function, while the original result stays the same?

We'll write a hook for `(*Transport).RoundTrip` in the standard library's `net/http` that only prints logs. The program sends one HTTP request; we build it with plain `go build` and with `otel go build`, then compare the output.

Before starting, [install `otel`](../index.md#installation) and make sure `otel version` works. Check [Compatibility](../user/compatibility.md) for Go and OpenTelemetry requirements. If your tool release isn't listed in the SDK compatibility table, open [`pkg/go.mod`](https://github.com/alibaba/loongsuite-go/blob/main/pkg/go.mod), switch to the tag or commit reported by `otel version`, and use the `go.opentelemetry.io/otel/sdk` version declared there. For a source build, read that file at the revision you built. Don't use the version from `main` for a different tool release.

## 1. Directory layout

Create a new directory for this lab:

```bash
mkdir -p hooklab/rules
cd hooklab
```

The tree below shows the completed lab. The root `go.mod` will be generated in step 2; `rules/go.mod` will be generated in step 4. Do not create those files yet.

```text
hooklab/
├── go.mod
├── main.go        # business program: sends one HTTP request
├── rule.json      # rule: find RoundTrip
└── rules/
    ├── go.mod
    └── hook.go    # hook: prints one line on entry and one on return
```

## 2. The program

`main.go` starts a local test server, sends it one GET request and prints the result. The OpenTelemetry SDK initialization in the code isn't relevant to this exercise and can be ignored.

```go
package main

import (
	"context"
	"fmt"
	"net/http"
	"net/http/httptest"

	"go.opentelemetry.io/otel"
	"go.opentelemetry.io/otel/sdk/trace"
)

func target(value int) int { return value + 1 }

func main() {
	provider := trace.NewTracerProvider()
	otel.SetTracerProvider(provider)
	defer provider.Shutdown(context.Background())
	_, root := otel.Tracer("guide").Start(context.Background(), "root")
	defer root.End()
	s := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) { w.WriteHeader(http.StatusNoContent) }))
	defer s.Close()
	res, err := http.Get(s.URL)
	if err != nil {
		panic(err)
	}
	defer res.Body.Close()
	fmt.Println("plain-result", target(41), "status", res.StatusCode)
}
```

In `hooklab/`, run the following, replacing `vX.Y.Z` with the compatible OTel version selected above (use the same version for both modules):

```bash
go mod init example.com/hooklab
OTEL_VERSION='vX.Y.Z'
go get "go.opentelemetry.io/otel@${OTEL_VERSION}" "go.opentelemetry.io/otel/sdk@${OTEL_VERSION}"
go mod tidy
```

## 3. The rule

`rule.json`:

```json
[
  {
    "ImportPath": "net/http",
    "Function": "RoundTrip",
    "ReceiverType": "\\*Transport",
    "OnEnter": "guideHttpEnter",
    "OnExit": "guideHttpExit",
    "Path": "./rules"
  }
]
```

## 4. The hook

`rules/hook.go`:

```go
package rules

import (
	"fmt"
	"net/http"
	_ "unsafe"

	"github.com/alibaba/loongsuite-go/pkg/api"
)

//go:linkname guideHttpEnter net/http.guideHttpEnter
func guideHttpEnter(call api.CallContext, t *http.Transport, req *http.Request) {
	fmt.Printf("hook-enter method=%s\n", req.Method)
}

//go:linkname guideHttpExit net/http.guideHttpExit
func guideHttpExit(call api.CallContext, res *http.Response, err error) {
	if err != nil {
		fmt.Printf("hook-error=%v\n", err)
		return
	}
	if res != nil {
		fmt.Printf("hook-exit status=%d\n", res.StatusCode)
	}
}
```

Check the three conventions from [Write the Hook Code](../dev/hook.md):

- The first parameter is `api.CallContext`.
- The remaining OnEnter parameters match the target's receiver and parameters: `(t *Transport) RoundTrip(req *Request)`.
- The remaining OnExit parameters match the target's return values: `(*Response, error)`.

`//go:linkname` connects these functions to the call sites generated by the tool, which is why `unsafe` is imported.

`rules/go.mod` declares the `pkg` module the hook depends on. During preprocessing, `otel` replaces it with the tool's embedded copy. You don't need to look up a matching pseudo-version or download the latest plugin dependencies. From `hooklab/`, create the module with a placeholder requirement:

```bash
(cd rules && go mod init guidehook && go mod edit -require=github.com/alibaba/loongsuite-go/pkg@v0.0.0)
```

The parentheses keep the following commands in `hooklab/`. Here `v0.0.0` is a placeholder for the instrumented build, not a version to download or use to build `rules/` on its own. The embedded replacement supplies the actual code. Unlike `pkg`, the application's OTel SDK version must be compatible with the tool, as selected in step 2.

## 5. Compare the two builds

Plain build:

```bash
$ go run .
plain-result 42 status 204
```

Build with `otel` from `hooklab/`. The rule's `"Path": "./rules"` is resolved relative to the build directory:

```bash
$ otel set -disable= -rule="$PWD/rule.json"
$ otel go build -o instrumented .
$ ./instrumented
```

The output contains:

```text
hook-enter method=GET
hook-exit status=204
plain-result 42 status 204
```

Both builds produce the same business result, `plain-result 42 status 204`; the instrumented program prints the two hook lines around the GET request. This shows the rule matched `RoundTrip`, the hook ran around the request, and the original result didn't change.

> [!NOTE]
> - `-disable=` keeps all default rules, and `-rule` adds yours on top. `-disable=all` disables the built-in library rules but keeps `base.json` and your custom rule; the built-in net/http spans would no longer be generated. See [CLI Reference](../user/config.md).
> - Telemetry export can make additional HTTP requests, so you may also see hook lines for POST requests. If no OpenTelemetry Collector is running locally, export failure logs may appear too. They don't affect this exercise. See [OpenTelemetry Settings](../user/sdk-config.md) for exporter settings.

`otel set` saves the custom rule in `.otel-build/conf.json`, so it also applies to later builds in this directory. After the experiment, clear it from `hooklab/`:

```bash
otel set -rule=
```

## No hook output?

Check from build time to run time:

1. Did the rule match? Search for `net/http` in `.otel-build/matched.json` and confirm your rule is there. See [Debugging](../hacking/debug.md) for more.
2. Did the build report errors? Check that the hook signatures match the target function.
3. Are you running `./instrumented`, not the plain program from `go run .`?
